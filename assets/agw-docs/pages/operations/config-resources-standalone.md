Manage agentgateway resources such as API keys at runtime through the admin API on the admin port (15000 by default), without editing your config file.

## About

The agentgateway admin process exposes a REST API for reading and writing config resources (such as virtual API keys, models, routes, and policies) at runtime. This is the same API the [Admin UI]({{< link-hextra path="/operations/ui" >}}) uses, and it is what lets you create, update, and revoke API keys without restarting the proxy.

The API is enabled when `config.storage.mode` is `hybrid`. In the default `file` mode, the config file is the only source of truth and these writes are not available.

> [!WARNING]
> The admin port (15000 by default) has **no authentication**. Anyone who can reach it can list, create, update, or delete keys. Bind it to localhost only (`127.0.0.1:15000`) and never expose it externally.

## Before you begin

Requires `config.storage.mode: hybrid` with a `config.database.url` so resources can be persisted:

```yaml
config:
  adminAddr: "127.0.0.1:15000"
  storage:
    mode: hybrid
  database:
    url: "postgres://user:password@host:5432/agentgateway"
```

## Resource kinds

The resource kind is written with dots, for example `llm.apiKey`. Using a bare name such as `apiKey` returns `unsupported config resource kind: apiKey`.

Common resource kinds include `modelCatalog`, `llm.provider`, `llm.model`, `llm.virtualModel`, `llm.apiKey`, `llm.policy`, `mcp.target`, `mcp.policy`, `mcp.settings`, `traffic.gateway`, `traffic.route`, `traffic.tcpRoute`, and `ui.policy`.

## List keys

```sh
curl -s http://127.0.0.1:15000/api/config/resources/llm.apiKey
```

Example response:

```json
{"resources": [{
  "kind": "llm.apiKey",
  "id": "03eafb4e-4c5d-480a-a870-cdf376976430",
  "value": {
    "key": "sk-agw-8a0b7a6a…",
    "metadata": {
      "id": "03eafb4e-…",
      "name": "my-service",
      "user": "alice"
    }
  },
  "revision": 1,
  "createdAt": "2026-08-13T11:22:44.357740Z",
  "updatedAt": "2026-08-13T11:22:44.357740Z"
}]}
```

## Create a key

Creation uses a **collection PUT** — the body wraps one or more records in a `resources` array:

```sh
curl -X PUT http://127.0.0.1:15000/api/config/resources/llm.apiKey \
  -H 'Content-Type: application/json' \
  -d '{"resources":[{"value":{
        "key":"sk-agw-<hex>",
        "metadata":{"name":"my-service","user":"alice","group":"engineering"}
      }}]}'
```

* The `id` is generated by the gateway; you do not send it.
* This is an **upsert**, not a replace — existing keys are preserved.

## Update a key

Update uses a **single-resource PUT** to `/…/llm.apiKey/{id}`. The key value is preserved, so a user keeps their key, for example when their group changes:

```sh
curl -X PUT http://127.0.0.1:15000/api/config/resources/llm.apiKey/<id> \
  -H 'Content-Type: application/json' \
  -d '{"value":{"key":"<existing key>","metadata":{"name":"my-service","user":"alice","group":"engineering"}}}'
```

| Behavior | Result |
| -- | -- |
| `key` (or `keyHash`) is required | Returns `422` if missing |
| Must keep the record's own format | Sending `keyHash` to a `key` record invalidates the key |
| Updating a nonexistent `id` | Returns `404` — this endpoint updates only, it does not create |
| `metadata` | Fully replaced, not merged — send all fields |
| Successful update | `revision` increments, `createdAt` is preserved |

## Delete a key

```sh
curl -X DELETE http://127.0.0.1:15000/api/config/resources/llm.apiKey/<id>
```

Returns `200` on success; deleting the same `id` again returns `404`.

## Propagation timing

A write to the admin API is not instantly visible on the traffic path. Measured values:

| Operation | Observed latency |
| -- | -- |
| Create → key valid | ~158 ms (an immediately following request can still get `403`) |
| Delete → key invalid | under 200 ms (the in-flight request may still complete) |

If a script creates a key and immediately uses it, add a retry.

## API keys in the config file vs. the admin API

| | Config file (`llm.policies.apiKey.keys`) | Admin API (`llm.apiKey` resource) |
| -- | -- | -- |
| Stored in | `config.yaml` | Database (`storage.mode: hybrid`) |
| Listed by the API | No | Yes |
| Deletable via the API | No | Yes |
| Changed by | Editing the file | The API / Admin UI |
| Use case | Emergency, when runtime management is unavailable | Normal operation |

Without `storage.mode: hybrid`, keys can only come from the config file.
