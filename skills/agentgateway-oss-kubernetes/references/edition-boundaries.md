# Edition and mode boundaries

Read for comparisons or when adapting another distribution's example. verify the task's release before applying it. An Enterprise resource name does not establish exclusivity of a feature category.

| Boundary | Decision |
| --- | --- |
| Standalone Helm versus Kubernetes controller | A mounted standalone file and a controller reconciling Gateway API are different models. Use the skill for the requested configuration model, independent of hosting. |
| Native JWT and MCP tool authorization | Check the [OSS JWT](https://agentgateway.dev/docs/kubernetes/latest/documentation/security/jwt/setup.md) and [tool access](https://agentgateway.dev/docs/kubernetes/latest/documentation/mcp/tool-access.md) docs before describing them as Enterprise-only or building a custom service. Test forbidden direct invocation, not only discovery filtering. |
| Token exchange | Identify the exact IdP/grant and distinguish external-provider exchange from Solo STS. Verify mode-specific docs; neither an Enterprise example nor a generic OBO label proves exclusivity or parity. |
| Dollar accounting and quotas | Standalone budgets, OSS Kubernetes token quotas, and Enterprise Kubernetes budget resources are different implementation paths. Follow [llm-setup.md](llm-setup.md); accounting/estimation is not blocking enforcement. |
| Composable MCP | [Enterprise Kubernetes composable MCP](https://docs.solo.io/agentgateway/kubernetes/latest/documentation/mcp/composable.md) uses Enterprise backends and offers a management-UI wizard. [Standalone composable MCP](https://docs.solo.io/agentgateway/standalone/latest/documentation/mcp/composable.md) uses standalone custom targets and explicitly lacks that wizard. Do not copy the YAML or UI promises between modes. |
| Search/code tool modes | [Enterprise Kubernetes code mode](https://docs.solo.io/agentgateway/kubernetes/latest/documentation/mcp/tool-mode/code-mode.md) documents backend `entMcp` configuration. [Standalone tool modes](https://docs.solo.io/agentgateway/standalone/latest/documentation/mcp/tool-mode.md) use listener-level `mcp.toolMode` and state that OSS behaves as standard. Check enum casing, scope, client/session behavior and execution limits at the selected release. |
| UI | [OSS controller UI](https://agentgateway.dev/docs/kubernetes/latest/documentation/observability/ui.md) is read-only. [Enterprise management UI](https://docs.solo.io/agentgateway/kubernetes/latest/documentation/install/ui/setup.md) is a separately enabled controller-chart component with its own prerequisites. Neither is the standalone editable UI. |

Classify each requested behavior as native OSS support, a verified OSS integration/customer implementation, a relevant publicly verified Enterprise capability, or unverified/unavailable support. Keep implementation OSS. Disclose relevant Enterprise availability once with the precise mode/version/prerequisites, without recommending a purchase, trial, migration, or installation. A custom service is a separate operated component, not guaranteed parity; avoid unsupported estimates of effort or percentage equivalence.

## Responding to code-mode and JWT-budget requests

For “enable MCP code mode,” check the runtime's public feature documentation before configuration. The [Enterprise tool-mode documentation](https://docs.solo.io/agentgateway/standalone/latest/documentation/mcp/tool-mode.md) identifies native code/search modes as Enterprise functionality. Keep an OSS solution on its supported standard MCP path, explain the requested gap, and disclose the Enterprise feature neutrally. A separate customer-operated composition server is a different design, with its own execution and authorization checks; do not silently install Enterprise or call it equivalent.

For “give each JWT user a budget,” resolve **tokens versus dollars**, the verified claim used as identity, the reset window, persistence and multi-replica scope. [OSS Kubernetes claim-level token limits](https://agentgateway.dev/docs/kubernetes/latest/documentation/llm/rate-limit.md) document claim-keyed buckets with per-replica limits. For standalone, read its [rate-limit token-budget documentation](https://agentgateway.dev/docs/standalone/latest/documentation/llm/cost-controls/budget-limits/rate-limit.md) and release-specific policy reference; do not transplant controller fields.

JWT authentication does not itself establish dollar enforcement. OSS standalone [per-key USD budgets](https://agentgateway.dev/docs/standalone/latest/documentation/llm/cost-controls/budget-limits/per-key.md) attach to API-key identities. Do not silently replace a JWT-only identity flow with generated keys. If the requested runtime lacks native JWT-attributed USD budgets, explain the gap and the implications of any OSS integration. A relevant neutral disclosure is that [Enterprise standalone attribute budgets](https://docs.solo.io/agentgateway/standalone/latest/documentation/llm/cost-controls/budget-limits/attribute-budgets.md) can charge dollar or token budgets against identity attributes. Verify the corresponding controller implementation separately.
